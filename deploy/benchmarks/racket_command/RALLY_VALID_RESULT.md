## Sample定义与冻结

仍在原39个位置上采样：X=-0.25m；原8×6网格裁掉最低Z行，39格有训练位置支持，
每格一个固定点，seed=42。每点最多5组方向，每组2档速度×2档TTS。

每组先附一个独立、合法的来球速度条件：此前越过球网、在己方半台反弹一次。
球拍目标法向、速度从该位置的导出训练联合支持域采样，并用碰撞/飞行模型检查：

- 球向对方运动，预计出球速度2..12m/s。
- 球底过网净空至少3cm，不能绕网侧面。
- 第一次落台在对方半台内，距近/远/左右边界至少10cm。
- 不从桌面下方穿入台面。
- 两档球拍速度从通过上述检查的采样值中选取，至少相差0.3m/s；不再强制用1.5/4.5两端。
- 同方向组的速度/TTS变体共享同一来球速度条件；TTS仍为0.28/0.50s。

在限定搜索预算内，37个位置找到组合，共178组方向、356组不同速度command，
乘两档TTS得到712条实际测试。35个点各20条，另两个点分别8条和4条；
另外两个点没有找到组合。未找到的68个计划样本不计为policy失败，也不作为证明不可达。
位置不替换，采样审计包含具体状态及所有成功组合。

冻结文件：`deploy/recordings/racket_command/rally_valid_suite_final_20261021/suite.json`。
每组保存来球速度、过去的己方反弹/越网位置、目标法向/方向/速度、预计落点和过网高度。
`load_suite()`复核command与见证一致性，并在1ms步长下复算。

独立使用原部署的Torch弹道/球网核函数再次检查全部356组不同速度command：
356/356预期有效回球，最小球底过网净空3.106cm，最小落点边界余量10.038cm。
校验只针对各自保存的来球条件和理想执行，不保证任意其他来球、旋转或策略执行下都回球有效。

## 复现和图表

```bash
.venv/bin/python -m deploy.benchmarks.racket_command.run \
  --suite deploy/recordings/racket_command/rally_valid_suite_final_20261021/suite.json \
  --render \
  --output "deploy/recordings/racket_command/rally_policy_$(date +%Y%m%d_%H%M%S)"
```

- `report.html`：完整交互图，默认联合达标率；包含采样计划/实际数量说明。
- `capability.png`：网格达标率及位置、法向、速度误差热力图。
- `points/point_*.png`：各点的方向分组、速度×TTS矩阵。
- `tracking_analysis.json`：上述分组和误差分位数。
- `physical_validity.json`：独立物理有效性复核。
- `suite.json`、`results.jsonl`、`traces/`：完整目标、逐样本输出和实际球拍轨迹。
