# 第二阶段中心区域：首批30个独立随机来球

本轮在本机MuJoCo运行，未连接或修改`.200`。
第一阶段入口/结果保留，第二阶段使用独立`deploy.benchmarks.receive.run`。

## 固定来球与真实运行链路

冻结文件：`deploy/recordings/receive/center_suite_20261021/suite.json`。
seed=42，在对面半台独立随机初始位置和速度，不读取motion、目标command或策略成绩。
只根据真实球轨迹几何检查合法越网、己方半台一次反弹、进入中心接球区域。

中心区域：X=-0.25m，Y=[-1.000,-0.525]m，Z=[0.12,0.42]m（桌面Z=0），
划分3×2格，每格5球，共30球。球在初始化后持续1ms积分，与实际移动拍面碰撞，
不在命令时刻瞬移、不覆写碰后球速或落点、不从参考motion反推来球。

运行时每180Hz送入一个位置样本，由现有二次拟合估计器得到速度，再调用原A3 planner，
经过现有motion选择器和G1 actor/PD。planner不获得球真值速度或未来交点/时刻；
未来交点仅用于离线验证与来球分格。默认没有观测噪声或额外延迟。
每球恢复同一准备状态和controller历史；每次只执行一次接球及回位。

## 两组同球对照

第一组保留`.200` A3实际配置中的目标[2.5,0,0]，Y=0在桌边。
第二组显式设置任务目标`--return-target 2.055 -0.7625`，为对方半台中心。
只改变任务落点输入；没有改变A3计算、球参数、关节动作、motion选择器或策略权重。
两组来球SHA256、每球选中motion及预测击球deadline均相同，逐项核对通过。

|指标|A3原边线目标|对方半台中心目标|
|---|---:|---:|
|完成评测|30/30|30/30|
|planner command被接受|30/30|30/30|
|实际碰拍|21/30（70%）|30/30（100%）|
|实际有效回球|12/30（40%）|11/30（36.67%）|
|完成回位|30/30|30/30|
|执行错误/失稳|0|0|
|严格command联合达标|0/30|3/30|

“有效回球”要求实际碰拍、越网、无触网、第一次桌面高度交点在对方台内，
不计地面反弹后回台，也不使用planner期望落点代替实际落点。
严格command指标是在指定deadline同时检查位置/法向/速度，并要求完成回位；
实际球可以在deadline前后碰拍形成有效回球，却仍不满足该严格跟踪指标。

两组planner位置误差中位数2.01mm、最大4.88mm；到达时间绝对误差中位数0.85ms、
最大1.32ms。命令锁定时剩余TTS为0.4812..0.4999s，来自真实估计与预测，没有手工指定。

## 理想球拍离线诊断

使用相同球初始状态，让理想球拍在接球附近按已经锁定的command位置、速度、法向
做局部直线运动，仍由相同球/拍碰撞模型决定结果。此诊断只用于分析，
没有进入真实机器人执行或采样筛选，不修改实际结果，也不是策略能力上限的证明。

|离线理想球拍|A3原边线目标|对方半台中心目标|
|---|---:|---:|
|碰拍|30/30|30/30|
|有效回球|17/30|30/30|

原边线目标组理想球拍的13次失败均为球心Y超过桌边约0.13..2.91mm；
当前有限桌面模型按球心判台内、不模拟边缘接触，因而判出界。该配置对边界误差敏感。
没有因此改动A3默认目标或物理；原结果保留，中心目标作为显式对照。

中心目标组中，理想执行30/30有效而实际仅11/30；加上规划误差较小，
本批主要问题更集中于实际拍心/法向/速度的联合跟踪和接触过程，而不是统一的TTS偏移。
仍包含原motion选择器影响，不能单独归因于网络权重。

```bash
.venv/bin/python -m deploy.benchmarks.receive.run \
  --suite deploy/recordings/receive/center_suite_20261021/suite.json \
  --return-target 2.055 -0.7625 \
  --render \
  --output "deploy/recordings/receive/center_replay_$(date +%Y%m%d_%H%M%S)"
```

去掉`--suite`可重新随机生成中心来球；`--seed`改变随机种子。
去掉`--return-target`使用原A3配置的边线目标。`--playback-rate 2`只改变播放速度，
不改变物理时间或TTS。两种目标都完成native viewer前两球检查，均保存了无头渲染截图。
